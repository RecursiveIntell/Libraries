# 11_BENCHMARK_PLAN

## Purpose

Do not use benchmarks as narrated self-esteem.
Use them as one honest live proof lane.

## Immediate benchmark target

### Benchmark 1 — degraded reason survives end-to-end

Goal:
- prove a kernel degradation reason survives scheduler -> runtime artifact -> schema -> query provenance

Inputs:
- one `budget_exhausted` fixture
- one `explicit_changed_nodes_required_for_delta` fixture

Success:
- the exact reason is visible without digging into raw scheduler structs

## Second benchmark target

### Benchmark 2 — episode + execution lineage survives tool runtime -> pilot -> verification

Goal:
- prove one end-to-end control decision can be traced back to episode identity and execution context without side-channel log archaeology

Success:
- one generated receipt chain and one rendered walkthrough

## What not to benchmark yet

- full v10 region geometry
- learned scheduling
- giant synthetic scoreboards

One real proof lane beats a deck full of fixture wins.
