# Package hygiene classification policy

## Principle

A source/context zip should not carry stale generated package files in the repo root. If generated output is needed for history, archive it under an evidence folder with a manifest. Root is for canonical source surfaces only.

## Root protected set

The following may remain in root:

- `README.md`
- `AGENTS.md`
- `Cargo.toml`
- `Cargo.lock`
- `pyproject.toml`
- `z.py`
- `LICENSE*`
- `CHANGELOG*`
- `CONTRIBUTING*`
- `SECURITY*`
- `.gitignore`, `.gitattributes`, `.editorconfig`

## Root generated/package residue set

The following should be moved automatically before packaging:

- previous zip archives
- previous `.manifest.json`, `.report.md`, `.excluded.json`, `.findings.json`
- previous `.codex-archive.json`
- bundle manifests/readmes generated by Codex bundle creation
- root audit/prompt/phase/risk/issue docs that are not canonical source docs

## Archive layout

Use one timestamped directory per cleanup operation:

```text
docs/source-packages/archive/20260522T061749Z/
  PACKAGE_ARTIFACT_ARCHIVE_MANIFEST.json
  files/
    README_BUNDLE.md
    BUNDLE_MANIFEST.json
    poly-kv-generic-rust-next-codex-context-20260520.report.md
    poly-kv-generic-rust-next-codex-context-20260520.codex-archive.json
```

## Manifest record fields

Each move must record:

- original path
- archived path
- sha256
- bytes
- mtime UTC
- reason
- classification
- run id if inferable
- whether same-hash duplicate was removed
- collision record if destination name had to be changed

## Non-goals

- Do not delete evidence without an archived copy unless same-hash archive already exists.
- Do not move current reserved output while the package is being written.
- Do not move canonical docs by fuzzy match alone.
- Do not include archive history in normal next-codex packages unless explicitly requested.
