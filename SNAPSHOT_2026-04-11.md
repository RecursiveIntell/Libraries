## 1. Identity & Purpose

**Libraries** is the upstream Rust workspace that provides the **constitutional finish line** for the kernel/oracle/runtime/verification stack. It is a 31-crate monorepo implementing:

- **Kernel & execution** — K2 deterministic execution, bounded exact/conservative oracles, conformance gates, recursive inference compilation
- **Runtime & runtimes** — orchestration scaffolds (knowledge-runtime, llm-tool-runtime), verification control planes, profile composition
- **Semantic layer** — hybrid vector search (HNSW + SQLite + FTS5), bridge/import law, memory forging with evidence bundles
- **Verification & governance** — typed adjudication, calibration, policy, control artifacts; governance observation surfaces
- **Identity & artifacts** — shared `stack-ids`, execution evidence families, canonical package contracts (EpisodeBundle, ClaimBundle, EvidenceBundle)

The mission is to **freeze the v9 constitutional finish line** while shaping (but not contaminating with) the v10+ runtime-geometry horizon.

**Relationship to Recall**: Libraries is the upstream library workspace. Recall is a downstream consuming application that vendors only critical libraries (`llm-pipeline`, `llm-output-parser`) into its own `deps/` for isolation; everything else is consumed via path dependency.

Per `CLAUDE.md` and `README.md`, the v9 finish line is reached when:

- v9 artifact families are frozen and schematized
- execution evidence is first-class queryable
- reference interpreters exist for hard semantic seams (bitemporal queries, bridge atomicity, repair invariants)
- bridge/runtime/repair invariants are executable and tested
- v10+ horizon items (right-graph law, convergence governance, region protocol) are shaped without leaking into v9

## 10. Relationship to Recall and Libraries2

**Libraries** is the upstream Rust workspace containing the full kernel/oracle/runtime/verification stack (31 crates).

**Recall** is a downstream consuming application that:
- Vendors only `llm-pipeline` and `llm-output-parser` into its own `deps/` for reproducibility/isolation
- Does NOT include the full Libraries workspace
- Consumes Libraries indirectly via vendored deps and path dependencies in its own `Cargo.toml`
- Is the application layer that orchestrates library primitives, whereas Libraries is the library layer that provides kernel, runtime, verification, and memory abstractions

**Libraries2** is a frozen, non-git staging snapshot of (a subset of) this workspace as of 2026-03-26, used as a planning surface for hostile-audit follow-up. Its `llm-tool-runtime` is a symlink back into THIS workspace.

In short: **Libraries is the upstream library stack frozen at the v9 constitutional finish line; Recall is a downstream consuming application; Libraries2 is a parallel staging snapshot.** Libraries owns governance, schemas, conformance gates, and reference semantics. Recall consumes the tested library contracts without re-solving governance.
