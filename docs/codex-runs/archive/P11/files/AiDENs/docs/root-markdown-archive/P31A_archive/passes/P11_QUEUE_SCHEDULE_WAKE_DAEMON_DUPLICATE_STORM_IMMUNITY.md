# P11 — Queue, schedule, wake, daemon, leases, and duplicate-storm immunity

## Phase

Memory/runtime core

## Purpose

Implement the autonomous execution substrate only after receipts, permits, memory, and tool safety are real.

## Why this pass exists

A daemon without leases/idempotency/receipts creates active job storms. The research recommends single-writer daemon, outbox, scheduler invariants, and safe mode before autonomy.

## Implementation steps

1. Define durable job identity, idempotency key, attempt family, lease owner, lease expiry, and occurrence key.
2. Implement one daemon-owned write queue and read-only CLI/UI observers.
3. Add safe mode, queue drain, cancellation, lease steal after expiry, and poison job quarantine.
4. Emit receipts for enqueue, dequeue, lease-acquire, execute, retry, cancel, duplicate-suppressed, and safe-mode transitions.
5. Add model-check-inspired regression tests for duplicate schedule occurrence, crash/restart, lease expiry, and cancellation resurrection.

## Acceptance gates

- Repeated same schedule occurrence cannot create duplicate logical jobs.
- Daemon restart preserves queued jobs and does not resurrect cancelled jobs.
- Safe mode blocks new risky jobs and allows inspection/drain.
