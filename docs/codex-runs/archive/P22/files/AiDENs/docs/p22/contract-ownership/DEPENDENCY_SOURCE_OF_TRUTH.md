# Dependency Source Of Truth

SOURCE BASIS: 2026-04-28

AiDENs uses `~/Coding/Libraries` as the canonical dependency source for stack owner crates. `~/Coding/Libraries2`, `~/Coding/Recall`, and `~/Coding/Recall-Coding` are reference-only and must not be wired as dependencies when a canonical owner exists in `~/Coding/Libraries`.

| Canonical concept | Owner crate | AiDENs dependency wiring | Phase decision |
| --- | --- | --- | --- |
| Identity and content-addressed stack IDs | `stack-ids` | Workspace dependency `path = "../stack-ids"`; consumed through workspace dependencies in AiDENs crates. | Canonical ID/digest owner remains outside AiDENs. |
| Attestation envelope | `attestation-exchange` | Workspace dependency `path = "../attestation-exchange"`; `aidens-contracts` depends through `attestation-exchange.workspace = true`. | `AttestationEnvelopeV1` is an explicit canonical re-export, not a local type. |
| Settlement and shared disposition | `federated-settlement` | Workspace dependency `path = "../federated-settlement"`; `aidens-contracts` depends through `federated-settlement.workspace = true`. | `SettlementCaseV1` and `SharedDispositionV1` are explicit canonical re-exports. |
| Mechanism theory artifacts | `mechanism-runtime` | Workspace dependency `path = "../mechanism-runtime"`; `aidens-contracts` depends through `mechanism-runtime.workspace = true`. | `TheoryVersionV1`, `TheoryRefuterSuiteV1`, and `HypothesisLibraryV1` are explicit canonical re-exports. |
| Remote oracle admission | `remote-oracle-admission` | Workspace dependency `path = "../remote-oracle-admission"`; `aidens-contracts` depends through `remote-oracle-admission.workspace = true` while remaining local admission/report surfaces are collapsed or quarantined in later phases. | Canonical owner is wired; no AiDENs-local replacement is introduced. |
| Canonical schema generation | `contract-schema-gen` | Workspace dependency `path = "../contract-schema-gen"`; canonical stack schema families are generated by owner crates through `contract-schema-gen`, not by AiDENs. | Phase 05 limits AiDENs schema output to non-authoritative AiDENs-local display/report DTO schemas. |
| Verification calibration | `verification-calibration` | Workspace dependency `path = "../verification-calibration"`; `aidens-governance-kit` depends through `verification-calibration.workspace = true`. | `CalibrationSnapshot` is imported from the canonical owner. |
| Pilot/control-loop receipts | `forge-pilot` | No Phase 03 AiDENs dependency is wired because current AiDENs code only contains report-string mentions, not typed pilot/control-loop receipt surfaces. | Add a dependency only if a typed pilot/control-loop surface is introduced or discovered. |
| Tool descriptors, calls, results, receipts, exposure runtime | `llm-tool-runtime` | Workspace dependency `path = "../llm-tool-runtime"`; `aidens-contracts`, `aidens-tool-kit`, `aidens-provider-kit`, `aidens-receipts`, and tests depend through workspace wiring. | Phase 06: AiDENs tool DTOs remain display/report wrappers with `CanonicalBackpointerV1`; tool input validation in `aidens-tool-kit` is delegated through `llm-tool-runtime::validate_arguments_against_schema` and canonical descriptor projection. |
| Boundary repair and schema/control receipts | `verification-control` | Workspace dependency `path = "../verification-control"`; `aidens-contracts`, `aidens-governance-kit`, and `aidens-repair-kit` depend through workspace wiring. | Phase 06: repair/schema DTOs carry `StackBoundaryRepairRecordId`, `StackControlReceiptId`, and canonical backpointer fields; missing concrete repair record IDs are quarantined rather than locally reinterpreted. |
| Runtime views, query traces, widening/degradation disclosure | `knowledge-runtime`, `semantic-memory`, `forge-memory-bridge` | Workspace dependencies remain under `~/Coding/Libraries`; runtime adapters live in `aidens-memory-kit` and CLI view surfaces report canonical owner metadata. | Phase 06: local runtime-view DTOs are display/report wrappers with canonical backpointers to query trace, widening disclosure, import receipts, and projection batches. |
| Kernel/region execution and bounded region compilation | `recursive-kernel-core`, `constraint-compiler`, `kernel-execution`, `kernel-oracles`, `kernel-conformance` | Workspace dependencies remain under `~/Coding/Libraries`; `aidens-contracts` depends on `recursive-kernel-core`, `constraint-compiler`-owned concepts are only referenced as backpointers, and `aidens-kernel-kit` invokes canonical compile/execute adapters. | Phase 06: region/residual/syndrome/kernel reports are display wrappers with typed stack ID backpointers or quarantine records; AiDENs does not own kernel execution law. |
| Support/retraction/subtraction semantics | `semantic-memory-forge` | Workspace dependency `path = "../semantic-memory-forge"`; `aidens-contracts` depends through `semantic-memory-forge.workspace = true`. | Phase 06: support, frontier, and subtraction DTOs are non-authoritative report wrappers pointing at canonical support/retraction families; unresolved lawful-subtraction owner depth is quarantined. |

No Phase 03 dependency points to `Libraries2`, `Recall`, or `Recall-Coding`. No local substitute crate or module was added for any missing canonical owner API.
