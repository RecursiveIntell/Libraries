# P31 Context Summary for Codex

P31 is the first executable compiler-front pass for v11A.

## Doctrine summary

The stack is moving toward a constitutional artifact runtime. That means material work must happen through typed artifacts, declared contracts, receipts, proof/debt surfaces, and conformance checks.

For this pass, the boundary layer is the priority. A structured boundary is not tolerant parsing. It is a compiler front-end for evidence. It must declare the language/dialect, schema, canonicalization, duplicate-key policy, coercion policy, unknown-field policy, repair policy, resource ceilings, trust boundary, treatment-critical paths, and allowed degradation behavior.

## Why P31 comes before graph compiler work

The v11A build order places boundary compiler profiles before reference/differential production paths. v11B graph/region execution depends on v11A semantics. Building the graph compiler before boundary contracts are executable risks compiling ambiguous or widened input into authoritative runtime state.

## What success looks like

A strict JSON payload crosses the boundary and either:

- is accepted with raw/canonical digests and parse receipt;
- is rejected with parse receipt and explicit error;
- is quarantined with parse receipt and explicit reason;
- is repaired only if repair is explicitly implemented and receipt-bearing.

No silent duplicate-key acceptance. No fake repair. No implicit treatment mutation. No graph compiler.
