# P17 — Attested exchange, trust roots, federation, and external artifact admission

## Phase

Federated horizon

## Purpose

Allow artifacts to cross runtime boundaries without creating a central truth plane or silently laundering remote claims.

## Why this pass exists

Federation is only safe after identity, time, execution evidence, conformance, and governance are solid. Remote artifacts must be admitted, disputed, and downgraded lawfully.

## Depends on

P16

- `RemoteOracleReceiptV1`

- `SettlementCaseV1`
- `SharedDispositionV1`

## Implementation steps

1. Define signed/attested artifact envelope with subject digest, producer, schema, time, policy, and signature/verification result.
2. Add admission policy that can accept, quarantine, downgrade, reject, or request additional witness.
3. Implement remote-oracle result import as advisory unless locally promoted through governance.
4. Add settlement cases for conflicting external claims while preserving local authority.
5. Add revocation/trust-root update receipts and re-evaluate affected admitted artifacts.

## Acceptance gates

- External artifact can be imported only through AdmissionDecisionV1.
- Remote contradiction creates settlement/dispute artifact, not direct overwrite.
- Trust-root revocation downgrades affected artifacts and emits receipts.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Forbidden shortcuts

- Do not let remote votes overwrite local truth.
- Do not accept unsigned external truth-bearing artifacts without quarantine/disclosure.
