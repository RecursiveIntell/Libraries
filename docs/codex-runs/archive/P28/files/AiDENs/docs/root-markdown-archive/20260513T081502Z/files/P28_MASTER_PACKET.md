# P28 Master Packet — AiDENs v11A Constitutional Material-Operation Kernel

## One-line objective

Turn AiDENs from a supported-local agent/runtime layer into a **v11A conformant core on declared local production paths**, where every material action is a typed, receipt-bearing transition over artifacts under declared semantic/proof/boundary law.

## Why P28 exists

P27 proved a supported-local path, strict package hygiene, and honest non-claims. v11A requires a stronger runtime law: material operations must have operator contracts, execution context envelopes, input/output manifests, receipts, proof/debt/degradation state, lifecycle transitions, and conformance fixtures.

Claude's audit adds a second hard truth: before adding more capability, the crate must fix concrete correctness, sandbox, packaging, timestamp, waiver, degradation, schema, and replay determinism bugs.

## P28 success definition

P28 succeeds only if:

1. All P0 Claude findings are fixed or quarantined as release blockers.
2. The declared local agent path has material operation contracts.
3. The declared path has execution context envelopes and per-call tool receipts.
4. Done states are impossible without required receipts.
5. Boundary compiler profiles exist for structured inputs/outputs.
6. Proof debt/waiver semantics are explicit and enforced.
7. Degradation/view disclosure is inspectable and cannot masquerade as exact.
8. Run bundles and event logs are immutable/replay-aware.
9. P28 package/replay evidence is self-consistent.
10. Support/profile/status docs do not overclaim v11.

## Declared production path for P28 conformance

```text
AgentSpecV1 validate/doctor/new
→ AiDENsRunner Plan/Act/Verify over mock/local provider
→ Tool dispatch: repo.read/list/stat/search, patch.propose/apply, run.checks
→ execution receipts + boundary compile receipts + proof/debt/degradation surfaces
→ final run report + AiDENsRunBundleV3 or v11 envelope wrapper
→ package validation + self-replay
```

## Non-goals

- No hosted provider enablement.
- No broad autonomy enablement.
- No daemon production claim.
- No full v11B regional runtime claim.
- No full v11C active federation/mechanism/self-hosting claim.
- No canonical memory/governance/kernel/provider/schema ownership migration into AiDENs.
- No new model capability before material-operation law exists.
