# P06 — Boundary compiler, schema validation, repair provenance, and canonical digests

## Phase

Contracted core

## Purpose

Upgrade JSON boundary handling from parse/repair helper to evidence-grade compiler front end.

## Why this pass exists

Parser and patch research is explicit: strict syntax, shape validation, canonicalization, bounded repair, and repair receipts are treatment integrity, not parser hygiene.

## Depends on

## Implementation steps

1. Declare accepted dialects: strict-json, json-schema-2020-12, rfc8785-canonical-json.
2. Reject duplicate keys and non-finite numbers where JSON semantics are ambiguous.
3. Add schema validation using generated schemas; validate schema documents against meta-schema.
4. Replace FNV-1a with cryptographic digest over RFC8785/JCS-style canonical JSON or a deterministic canonicalizer with declared limits.
5. Turn markdown-fence and substring repair into bounded, policy-controlled repair classes with before/after digests.

## Acceptance gates

- Duplicate-key fixture is rejected with DuplicateKeyFindingV1.
- Schema-invalid tool input is blocked before invocation and emits SchemaValidationReceiptV1.
- Canonical digest is cryptographic, deterministic, and stable across whitespace/key-order changes.
- Repair cannot change treatment-critical fields without a treatment-integrity warning or hard fail.
