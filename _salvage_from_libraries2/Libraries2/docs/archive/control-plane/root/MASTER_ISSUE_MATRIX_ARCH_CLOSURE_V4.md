# Master Issue Matrix — Architecture Closure V4

Generated from static inspection of `new3.zip` on 2026-03-08.

## Scope
This matrix is optimized for **finishing architecture safely** from the current full snapshot. It prioritizes remaining architecture-closure work over speculative refactors. It is based on **static inspection only** in this environment: no full workspace build or test execution was performed here.

## How to read this
- **compat_debt** = migration-only or compatibility surface that may fossilize
- **impl_lag** = target architecture is known, implementation still incomplete
- **decision_gap** = semantics are workable now but still need an explicit architecture decision
- **hardening_gap** = enforcement exists but is weaker than desired
- **test_gap** = proof coverage is not yet strong enough to claim closure
- **doc_drift** = docs likely to misdescribe the code after changes unless updated

## Priority order

## P0

- **BRG-001 — forge-memory-bridge — forge-memory-bridge/src/batch.rs::{schema_version,export_schema_version}**: Import/export version vocabulary is still muddier than ideal. Batch carries both schema_version and export_schema_version, and V1 intentionally mirrors them.
- **BRG-002 — forge-memory-bridge — forge-memory-bridge/src/transform.rs::transform_record(ExportRecord::Claim)**: Version-level claim supersession lineage is still incomplete. Export carries supersedes_claim_id, not supersedes_claim_version_id, so the bridge leaves supersedes_claim_version_id=None.
- **SM-003 — semantic-memory — semantic-memory/src/lib.rs::{EntityAlias,EvidenceRef,Episode} import branches**: Core claim/relation imports are now strict, but non-core records still default some secondary semantics (alias review_state/human flags/confidence, evidence source_authority fallback, episode cause_ids/confidence defaults). Some defaults are probably fine; some may be too permissive for final canonical mode.
- **SM-004 — semantic-memory — semantic-memory/src/projection_storage.rs::entity_aliases table**: Entity alias storage lacks DB-level enum/check constraints for review_state and merge_decision. Application-level defaults exist, but SQLite does not currently prevent invalid values from landing.
- **KR-001 — knowledge-runtime — knowledge-runtime/src/runtime.rs::query_with_trace temporal path**: Temporal execution remains best-effort post-filtering with downgrade warnings instead of true temporal retrieval over imported temporal metadata.
- **KR-002 — knowledge-runtime — knowledge-runtime/src/runtime.rs::query_with_trace scope handling**: Scope enforcement beyond namespace remains partial. Runtime warns or errors, but upstream search still cannot push domain/workspace/repo filters.
- **KR-003 — knowledge-runtime — knowledge-runtime/src/runtime.rs::{projection tracker, rebuild hooks}**: Projection lifecycle tracking exists, but rebuild execution remains observability-only. Callers still have to drive actual rebuild behavior.
- **KR-005 — knowledge-runtime — knowledge-runtime/tests/cross_crate_proof.rs and ugly_case_tests.rs**: Cross-crate proof coverage improved, but replay / queue-hop lineage, strict-scope failure semantics, and runtime consumption of Forge-derived evidence still need stronger proof.
- **AG-001 — agent-graph — agent-graph/src/graph.rs::{legacy_trace_id,to_legacy_trace_id} and event_sink.rs**: Agent-graph still emits legacy trace_id strings on important event surfaces even though canonical trace/retry fields now exist.
- **E2E-001 — cross-crate — knowledge-runtime/tests/cross_crate_proof.rs + forge-memory-bridge/tests + semantic-memory/tests + semantic-memory-forge tests**: The stack still needs a final architecture-closure proof matrix spanning Forge export, bridge transform, memory import, runtime query, and trace/retry visibility.
- **DOC-001 — root/docs — README.md, CLAUDE.md, crate READMEs affected by closure work**: Docs are likely behind the latest code-level reality after the next closure pass unless explicitly updated.

- **FMF-001 — semantic-memory-forge — semantic-memory-forge/src/{bundle.rs,envelope.rs,estimator.rs}**: Forge substrate is doctrinally aligned, but still not fully wired end-to-end into export -> bridge -> memory -> runtime proof. It is mostly schema/substrate plus local tests.
- **JQ-001 — job-queue — job-queue/src/types.rs::{trace_id,with_trace_id,trace_ctx_compat}**: Legacy trace string compatibility remains on the public job type and builder surface.
- **JQ-002 — job-queue — job-queue/src/db.rs::{trace_id,attempt_count,attempt_id,trial_id}**: DB still persists legacy trace_id and attempt_count alongside canonical attempt_id/trial_id. Transitional, but cleanup risk remains.
- **AG-002 — agent-graph — agent-graph/src/event_sink.rs::{attempt,attempt_id,trial_id} and retry paths in graph.rs**: Dual-world retry metadata remains on events: legacy attempt counters coexist with canonical AttemptId/TrialId.

- **SID-001 — stack-ids — stack-ids/src/trace.rs::{from_legacy_trace_id,to_legacy_trace_id}**: Legacy trace conversion helpers remain as public migration seams. Keep them, but prevent new normal-path call sites from depending on legacy trace strings.
