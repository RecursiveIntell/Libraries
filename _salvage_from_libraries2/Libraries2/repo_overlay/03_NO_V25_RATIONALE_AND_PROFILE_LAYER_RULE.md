
# No-v25 rationale and profile-layer rule

## Core rule

Do **not** draft a speculative `v25` unless a future seam:
1. cuts across multiple existing owner crates,
2. cannot be expressed as a profile, library, or local doctrine under existing law, and
3. would otherwise force semantic duplication or contradiction.

That bar is intentionally high.

## Why this rule exists

By v24 the stack already has:
- truth and evidence law,
- execution evidence,
- recursive semantics and contradiction law,
- attested exchange and remote admission,
- federated settlement,
- mechanism and theory search,
- discovery economics,
- institutional memory,
- self-hosting constitutional execution,
- live effect law,
- delegated authority law,
- deployability and assurance law,
- and continuity / incident law.

The remaining work is not another cross-cutting architecture turn.
It is structured configuration over that law.

## Profile-layer rule

If the candidate can be expressed as:
- policy tables,
- control mappings,
- role catalogs,
- deployment envelopes,
- trust-root bindings,
- hazard libraries,
- pager routes,
- tenancy or locality envelopes,
- or vendor translation adapters,

keep it out of the base-spec sequence.

## What this pass therefore does

This pass creates seven profile specs:
- P1 privacy / retention / disclosure / redaction
- P2 locality / tenancy / residency / boundary overlay
- P3 role catalog / duty segregation / approval matrix
- P4 regulated deployment / control mapping / recertification
- P5 sector hazard library / monitor catalog / mitigation playbook
- P6 vendor certification adapter / external evidence translation
- P7 incident taxonomy / escalation / pager routing
