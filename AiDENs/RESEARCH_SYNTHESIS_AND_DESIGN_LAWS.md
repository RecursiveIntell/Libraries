# Research Synthesis and Design Laws

The latest research corpus is coherent. It is not asking for one more feature; it is asking for a stack that can testify.

## Strongest recurring themes

### 1. Typed artifacts are the real substrate

The architecture should be a machine that produces, verifies, repairs, supersedes, compacts, and exchanges typed artifacts. Logs and prose are secondary.

Required artifact families include execution receipts, episode bundles, evidence bundles, verification plans, repair records, contradiction findings, schemas, witness/certificate outputs, region messages, and admission/settlement artifacts.

### 2. Execution is evidence

Retries, queue hops, provider routes, tool exposure, tool invocation, deadlines, budget exhaustion, fallback, widening, and degradation change what an output means. They must be receipt-bearing, durable, and queryable.

### 3. Time is part of meaning

Valid time and recorded/transaction time must stay separate. Memory cannot be unversioned notes. A claim must answer both “what was true then?” and “what did we believe then?”

### 4. Boundary handling is a compiler front end

Structured output handling must enforce syntax, shape, semantics, repair provenance, canonical digesting, duplicate-key rejection, and treatment integrity. Lenient parsing creates epistemic rot.

### 5. Reference semantics are mandatory

If a behavior is normative, there must be a reference interpreter or conformance oracle for it. This starts with provider route, tool exposure, permits, boundary repair, receipt lineage, and later temporal query semantics.

### 6. Contradictions are objects, not score drops

A contradiction should produce a typed finding with evidence, syndrome/residual when applicable, repair candidates, quarantine state, and resolution history.

### 7. The right graph matters

Storage graph, retrieval graph, inference graph, repair graph, and control graph are different objects. Collapsing them into one graph is an architectural error.

### 8. Small communicating regions beat giant graph chatter

The runtime should eventually execute through small regions that exchange typed artifacts, not shared mutable global state.

### 9. Subtraction is first-class

A complete system must remove, compact, summarize, and minimize with receipts and invariant preservation. Destructive deletion is not lawful subtraction.

### 10. Learning remains downstream

Learned ranking, scheduling, calibration, and triage can assist. They cannot rewrite truth, identity, time, causal semantics, or promotion law.

## Governing laws for Codex

1. Evidence before inference.
2. Execution evidence before daemon autonomy.
3. Contracts before cross-crate complexity.
4. Reference semantics before clever kernels.
5. Memory before repair/promotion.
6. Verification before promotion.
7. Local repair before global rebuild.
8. Explicit degradation before silent approximation.
9. Content identity plus logical identity before federation.
10. Human challenge and rollback remain available.
