# P01 — Public API honesty, no-op removal, and plan/runtime parity

## Phase

Foundation / honesty

## Purpose

Remove or implement API methods that accept inputs without honoring them; align app plans, builder inputs, and runtime configuration.

## Why this pass exists

A silent no-op API is more dangerous than a missing API because it produces false operator confidence. from_plan currently ignores provider detail and app-plan/provider/runtime parity is incomplete.

## Depends on

P00

## Primary crates / surfaces

- `aidens-app-kit`
- `aidens-runner`
- `aidens-cli`
- `aidens-contracts`

## Artifact families introduced or hardened

- `ApiHonestyReceiptV1`
- `PlanRuntimeParityReportV1`
- `ConfigApplyReceiptV1`

## Implementation steps

1. Audit every public builder and CLI path for ignored inputs.
2. Make AiDENsApp::from_plan either require provider information in the plan or fail with an explicit provider-unbound error.
3. Ensure custom ToolRegistry passed to app builder is preserved and observable through inspect-tools/list-tools.
4. Add plan-to-runner parity tests for provider, memory mode, receipt level, enabled tool bundles, and sandbox root.
5. Reject MemoryMode::Required unless a concrete memory store is configured.

## Acceptance gates

- No public method accepts meaningful input and silently discards it.
- from_plan cannot produce a disabled-provider runner when provider_required=true unless the plan explicitly selects disabled and returns a blocked run.
- plan compile output and doctor report agree on provider route, tool exposure, memory mode, and scaffold state.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Required command gate

```bash
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
bash scripts/verify.sh
```

If a command cannot run in the local environment, Codex must record the exact command and reason in the handoff packet.

## Forbidden shortcuts

- Do not fix no-ops by hiding methods behind doc comments only.
- Do not treat disabled provider as a valid provider when provider_required=true.
