# P13 — Multi-view runtime, retrieval disclosure, and query widening law

## Phase

Runtime/query core

## Purpose

Expose semantic, temporal, entity, causal, control, and execution views without collapsing them into one shadow database.

## Why this pass exists

The architecture differentiates raw truth, projected truth, execution truth, control truth, and advisory judgment. Query widening is a policy event, not invisible fallback.

## Depends on

P12

- `ProjectionDigestV1`
- `DegradationEventV1`

## Implementation steps

1. Define view modes: semantic, temporal, entity, causal, control, execution, combined-with-disclosure.
2. Every query must state valid/recorded time behavior, identity expansion policy, scope, and widening/fallback rules.
3. Add disclosure receipts when retrieval widens entity aliases, time windows, scope, or fallback index.
4. Separate projections/caches from authoritative memory with rebuild-from-source tests.
5. CLI query commands must print view mode and degradation reason before result details.

## Acceptance gates

- A time-scoped query cannot silently fall back to timeless retrieval.
- Alias expansion/widening emits QueryWideningReceiptV1.
- Projection rebuild from memory/evidence produces identical digest under same policy.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Forbidden shortcuts

- Do not let runtime become a second durable truth store.
- Do not merge execution receipts into domain truth without explicit relation artifacts.
