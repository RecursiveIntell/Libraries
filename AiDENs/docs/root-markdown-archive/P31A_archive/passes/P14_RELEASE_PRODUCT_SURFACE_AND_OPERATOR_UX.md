# P14 — Release-grade product surface, operator UX, and status truth

## Phase

Product readiness

## Purpose

Make AiDENs usable as a product/platform: clear commands, diagnostics, docs, packaging, examples, and release bar.

## Why this pass exists

Completion means the system can be operated without bespoke developer archaeology. Product truth must match code truth.

## Depends on

P13

## Primary crates / surfaces

- `aidens-cli`
- `aidens-app-kit`
- `aidens`
- `docs`
- `examples`
- `CI`

## Artifact families introduced or hardened

- `ReleaseReadinessReportV1`
- `OperatorStatusReportV1`
- `ExampleAppManifestV1`
- `InstallSmokeReceiptV1`

## Implementation steps

1. Update examples for chat-only, coding, memory, daemon, and research profiles; mark unsupported advanced features honestly.
2. Add commands: status, doctor, receipts, schemas, memory, queue, permits, run, tools, provider-check, package.
3. Add end-to-end smoke scripts for disabled, mock, ollama, and one API provider fixture path.
4. Produce release readiness report with supported/partial/deferred matrix.
5. Ensure README quickstart has no impossible command or unsupported feature claim.

## Acceptance gates

- A new user can create an app, run provider-check, inspect tools, run mock turn, inspect receipts, and run verify.sh.
- Release readiness report blocks if any public docs claim a scaffolded crate is complete.
- CI exercises examples as compile/test fixtures.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Required command gate

```bash
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
bash scripts/verify.sh
```

If a command cannot run in the local environment, Codex must record the exact command and reason in the handoff packet.

## Forbidden shortcuts

- Do not document horizon features as available.
- Do not hide degraded modes in friendly prose.

## Handoff output

At pass completion, create or update:

- pass completion section in `STATUS.md` or equivalent;
- issue matrix rows marked done/blocked/deferred;
- receipts/fixtures/schemas generated by this pass;
- `CodexPacketV1` or a markdown handoff with commands run, failures, files changed, and unresolved blockers.
