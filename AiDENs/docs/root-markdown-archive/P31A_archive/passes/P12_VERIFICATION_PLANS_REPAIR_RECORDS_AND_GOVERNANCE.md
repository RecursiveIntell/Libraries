# P12 — Canonical verification, repair, contradiction, and governance adapters

## Phase

Governed runtime

## Purpose

Make risk-bearing outputs route through canonical verification, refutation, repair, and governance library artifacts before promotion.

## Why this pass exists

The causal/research corpus is explicit: claims need treatment/outcome/confounder/evidence/refutation bundles. Contradictions must be typed, not hidden score drops.

## Depends on

P11

## Primary crates / surfaces

- `aidens-governance-kit`
- `aidens-repair-kit`
- `aidens-arbiter-kit`
- `aidens-contracts`
- `aidens-memory-kit`
- `aidens-receipts`

## Artifact families introduced or hardened

- `verification_control::CheckPlan`
- `verification_control::ControlReceipt`
- `verification_control::BoundaryRepairRecord`
- `verification_adjudication::PromotionDecision`
- `semantic_memory_forge::EvidenceBundle`
- `semantic_memory_forge::ContradictionWitnessV1`

## Implementation steps

1. Build canonical verification cases, check plans, attempts, and control receipts.
2. Use Forge evidence bundles and refutation artifacts directly.
3. Validate canonical contradiction witnesses instead of local contradiction states.
4. Emit canonical repair records with replay lineage.
5. Call canonical promotion/adjudication decisions; no output self-promotes.

## Acceptance gates

- Risk-bearing claims route through canonical verification-control/policy/adjudication artifacts.
- Contradiction uses canonical Forge witnesses and does not silently overwrite memory.
- Repair emits canonical verification-control or Forge repair lineage.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Required command gate

```bash
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
bash scripts/verify.sh
```

If a command cannot run in the local environment, Codex must record the exact command and reason in the handoff packet.

## Forbidden shortcuts

- Do not call a ranking score “verified”.
- Do not delete contradicted claims; supersede or quarantine them.

## Handoff output

At pass completion, create or update:

- pass completion section in `STATUS.md` or equivalent;
- issue matrix rows marked done/blocked/deferred;
- receipts/fixtures/schemas generated by this pass;
- `CodexPacketV1` or a markdown handoff with commands run, failures, files changed, and unresolved blockers.
