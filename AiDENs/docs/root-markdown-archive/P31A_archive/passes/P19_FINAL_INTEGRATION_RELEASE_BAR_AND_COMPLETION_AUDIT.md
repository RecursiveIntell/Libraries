# P19 — Final integration, release bar, and completion audit

## Phase

Release proof

## Purpose

Run cross-pass integration, package the release, and generate a falsifiable completion report that says exactly what is done, partial, deferred, and blocked.

## Why this pass exists

Completion requires an end-to-end proof, not a pile of passed unit tests. The final pass protects against constitutional drift and scope laundering.

## Depends on

P18

## Primary crates / surfaces

- `workspace root`
- `all crates`
- `docs`
- `CI`

## Artifact families introduced or hardened

- `CompletionAuditReportV1`
- `ReleaseArtifactManifestV1`
- `CrossPassTraceabilityMatrixV1`
- `KnownLimitationsRegisterV1`
- `RegressionDebtLedgerV1`

## Implementation steps

1. Run all acceptance gates and produce machine-readable results.
2. Generate traceability matrix: requirement -> pass -> crate -> tests -> artifacts -> docs.
3. Package schemas, fixtures, examples, scripts, AGENTS.md, and docs into release artifacts.
4. Audit docs for false claims, stale metrics, and unsupported feature promises.
5. Create final “complete / near-complete / deferred horizon” report with explicit blockers and next roadmap.

## Acceptance gates

- cargo fmt/check/test/clippy pass for workspace with all features.
- All pass acceptance gates are satisfied or explicitly waived by governance artifact.
- Completion report contains no unsubstantiated “healthy” claim for incomplete advanced surfaces.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Required command gate

```bash
cargo fmt --all --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features -- -D warnings
bash scripts/verify.sh
```

If a command cannot run in the local environment, Codex must record the exact command and reason in the handoff packet.

## Forbidden shortcuts

- Do not ship without a current limitations register.
- Do not mark horizon features complete to close the plan.

## Handoff output

At pass completion, create or update:

- pass completion section in `STATUS.md` or equivalent;
- issue matrix rows marked done/blocked/deferred;
- receipts/fixtures/schemas generated by this pass;
- `CodexPacketV1` or a markdown handoff with commands run, failures, files changed, and unresolved blockers.
