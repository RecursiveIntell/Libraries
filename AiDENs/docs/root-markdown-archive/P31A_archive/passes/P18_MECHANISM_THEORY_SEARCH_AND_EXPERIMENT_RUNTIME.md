# P18 — Mechanism/theory search, experiment runtime, and falsifiable model library

## Phase

Mechanism horizon

## Purpose

Represent candidate mechanisms, simulators, fit runs, stability reports, and theory refuter suites as lawful artifacts.

## Why this pass exists

After experiments and evidence are lawful, the next frontier is not a model zoo; it is mechanisms as replayable, falsifiable artifacts.

## Depends on

## Implementation steps

1. Define mechanism/theory artifact model: assumptions, variables, equations/program, simulator contract, evidence support, refuters, stability/invariance reports.
2. Add search-program artifact for symbolic/sparse/neural/hybrid mechanisms without promotion by score alone.
3. Require fit runs to record dataset, execution context, seed, optimizer, nuisance state, and result digest.
4. Publish theory only after refuter suite and governance disposition.
5. Allow multiple observationally equivalent mechanisms to coexist with explicit non-identification disclosure.

## Acceptance gates

- A candidate mechanism can be fit, refuted, versioned, superseded, and replayed from artifacts.
- High score alone cannot promote theory without refuter/gov artifacts.
- Equivalent mechanisms remain distinct unless an explicit equivalence/alias decision is admitted.

## Required tests

- Unit tests for all new artifact constructors and policy decisions.
- Integration tests covering the pass's primary CLI/runtime behavior.
- Golden fixture tests for any schema- or receipt-bearing artifact.
- Regression tests for every bug or counterexample found during the pass.

## Forbidden shortcuts

- Do not store theory updates as notebook comments or raw model weights only.
- Do not confuse observational equivalence with causal identification.
